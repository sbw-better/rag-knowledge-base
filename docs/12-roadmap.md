# 生产级演进路线

## 阶段一：工程和体验补强

- 完善项目文档体系。
- 增加更多集成测试。
- 增加操作审计写入。
- 增加全局通知、任务历史、上传进度。
- 增加后端分页接口。
- 增加日志 requestId 前后端贯通。

## 阶段二：权限和多租户

- 完整组织、租户、用户管理。
- 当前已有 `ADMIN`、`KB_MANAGER`、`USER` 系统角色，以及知识库 owner/member 基础能力；后续细化 Owner、Editor、Viewer 的差异行为。
- 管理员后台继续补齐账号禁用、密码重置、授权审计。
- 审计日志查询页面。
- Refresh Token 和 token 撤销。
- 同一前端应用内按角色展示管理功能和普通问答功能，不拆两个应用。

## 阶段三：检索能力升级

当前已经使用 Milvus 作为向量检索底座，MySQL 作为业务事实库和关键词检索兜底。

后续增强：

- Rerank 模型。
- 更完整的混合检索策略。
- 按文档、标签、时间范围过滤。
- Query rewrite 和多路召回。
- 引入 OpenSearch 承载 BM25、中文分词、复杂过滤和高亮。

## 阶段四：向量索引治理

- 已提供按知识库重建 Milvus 索引的管理接口；后续应改造成异步任务并记录进度。
- 提供按文档重建 Milvus 索引的管理接口。
- 记录索引版本、Embedding 模型、维度和创建时间。
- 维度变化时阻止混写，并提示必须重建 collection。
- 对 Milvus 写入失败提供可重试任务。

## 阶段五：数据库和持久层深化

当前已经完成 MySQL + MyBatis-Plus + BIGINT 雪花 ID 改造。后续重点不是再换持久层，而是补齐生产能力：

- Mapper SQL 分页和筛选。
- 数据库唯一约束和幂等约束补强。
- 审计表落库。
- 乐观锁或状态机控制任务并发。
- 数据备份、恢复和归档策略。

## 阶段六：异步和实时能力

- RabbitMQ/Kafka 替代 DB 轮询任务。
- WebSocket/SSE 推送任务状态。
- SSE 流式问答输出。
- 后台任务重试、取消、优先级。

## 阶段七：文档理解增强

- OCR。
- 表格解析。
- 图片和图表摘要。
- 文档结构化解析。
- 文档版本管理。
- 文档在线预览。

## 阶段八：生产运维

- Prometheus 指标。
- Grafana Dashboard。
- 集中日志。
- 告警规则。
- 备份恢复。
- 灰度发布。
- 容灾部署。
