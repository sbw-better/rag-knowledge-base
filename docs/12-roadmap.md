# 生产级演进路线

## 阶段一：工程和体验补强

- 完善项目文档体系。
- 增加更多集成测试。
- 增加操作审计写入。
- 增加全局通知、任务历史、上传进度。
- 增加后端分页接口。
- 增加日志 requestId 前后端贯通。

## 阶段二：权限和多租户

- 完整组织、租户、用户管理。
- 知识库成员权限：Owner、Editor、Viewer。
- 管理员后台。
- 审计日志查询页面。
- Refresh Token 和 token 撤销。

## 阶段三：检索能力升级

- Rerank 模型。
- BM25 检索。
- 更完整的混合检索策略。
- 按文档、标签、时间范围过滤。
- Query rewrite 和多路召回。
- 引入 OpenSearch 承载全文检索。

## 阶段四：向量数据库升级

当前使用 PostgreSQL + pgvector，适合 MVP 和中小规模场景。

后续可选：

- Milvus：专用向量数据库，适合大规模向量召回。
- OpenSearch：全文检索、混合检索、过滤和排序能力强。
- Elasticsearch：企业内已有 ES 体系时可复用。

建议迁移路径：

1. 保留 PostgreSQL/MySQL 存业务数据。
2. `document_chunks` 保留文本和元数据。
3. 向量写入 Milvus/OpenSearch。
4. 检索服务通过接口屏蔽底层实现。

## 阶段五：数据库和持久层改造

后续可以迁移为：

- MySQL：业务数据主库。
- MyBatis-Plus：替代 JPA，增强 SQL 可控性。
- Flyway：继续管理表结构变更。
- Milvus/OpenSearch：承载向量或全文检索。

迁移原则：

- API 响应结构保持兼容。
- 文档、切片、任务、会话核心语义保持兼容。
- DTO 继续跟随业务模块放置，避免重新聚合到公共大类。
- 先双写或离线迁移，再切换检索读路径。

## 阶段六：异步和实时能力

- RabbitMQ/Kafka 替代 DB 轮询任务。
- WebSocket/SSE 推送任务状态。
- SSE 流式问答输出。
- 后台任务重试、取消、优先级。

## 阶段七：文档理解增强

- OCR。
- 表格解析。
- 图片和图表摘要。
- 文档结构化解析。
- 文档版本管理。
- 文档在线预览。

## 阶段八：生产运维

- Prometheus 指标。
- Grafana Dashboard。
- 集中日志。
- 告警规则。
- 备份恢复。
- 灰度发布。
- 容灾部署。
