# 前端设计说明

## 技术栈

- Vite
- React 19
- TypeScript
- React Router
- TanStack Query
- Axios
- Tailwind CSS
- lucide-react

## 页面结构

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/login` | 登录页 | 用户登录 |
| `/register` | 注册页 | 用户注册 |
| `/app` | 工作台首页 | 工单、知识库和管理动作概览 |
| `/app/support-tickets` | 工单工作台 | 工单队列、详情、处理动作和 AI 回复 |
| `/app/support-tickets/:id` | 工单详情 | 在工作台内打开指定工单 |
| `/app/knowledge-bases` | 知识库目录 | 创建、搜索和进入知识库 |
| `/app/knowledge-bases/:id` | 知识库详情 | 文档、检索、问答、成员、配置、运维 |
| `/app/users` | 用户管理 | 管理用户平台角色 |
| `/app/tenants` | 租户管理 | 创建和查看租户边界 |
| `/app/audit-logs` | 审计日志 | 查看关键管理动作 |

## 工作台布局

- 桌面左侧：品牌、服务分组导航、知识库快捷入口和可收缩开关。
- 移动底部：固定服务导航，包含首页、工单、知识和管理入口。
- 顶部：当前服务标题和右上角账户菜单。
- 主区域：根据路由显示工作台概览、业务处理、知识运营或系统管理。

导航定义集中在 `src/pages/workspace-navigation.tsx`，避免每次新增页面都改动布局壳。

## 页面模块边界

大型页面拆成“页面壳 + 领域组件”的结构：

- `WorkspaceHomePage.tsx`：只负责首页数据查询和路由跳转；`pages/workspace-home/` 放首页概览组件。
- `SupportTicketsPage.tsx`：只负责工单查询、筛选状态、mutation 和路由；`pages/support-tickets/` 放队列、详情、沟通流、侧栏、弹窗和共享状态组件。
- `KnowledgeBasesPage.tsx`：只负责知识库目录查询、分页、创建提交和跳转；`pages/knowledge-bases/` 放目录列表和创建弹窗。
- `KnowledgeBasePage.tsx`：只负责知识库详情页壳、权限判断和 Tab 切换；`pages/knowledge-base/` 放文档、聊天、检索、成员、配置、运维面板。
- `UsersPage.tsx`、`TenantsPage.tsx`、`AuditLogsPage.tsx`：复用 `pages/admin/` 的后台管理页容器、筛选栏、记录卡片和审计标签。

新增复杂页面时，优先保持页面文件在 150 行左右；数据编排留在页面壳，展示组件放入对应领域目录。

## 工作台首页

首页不是纯导航页，而是轻量概览：

- 今日处理：全部工单、待处理、处理中、已逾期。
- 售后运营看板：今日/近 7 天/近 30 天窗口切换、趋势对比、坐席维度、平均首响、SLA 达成率、AI 辅助回复、知识命中率、待补知识、客服外发、无答案排行，以及分类/渠道/优先级分布。
- 知识库状态：展示常用知识库、可维护状态和检索参数。
- 最近管理动作：管理员可见，审计动作和目标类型以中文标签展示。

## 知识库详情页

详情页使用 Tabs：

- 文档：上传文件、查看当前知识库文档任务。
- 检索：选择 `VECTOR`、`KEYWORD`、`HYBRID` 模式测试召回。
- 问答：基于当前知识库进行 RAG 对话，展示引用来源；普通用户只看到该入口。
- 成员：管理当前知识库可访问用户，支持搜索、多选和批量授权。
- 配置：修改知识库名称、描述、切片参数和默认 TopK。
- 运维：重建 Milvus 向量索引，以及删除知识库等低频高风险操作。

详情页按后端返回的能力字段展示入口：`VIEWER` 只显示问答，`EDITOR` 增加文档和检索，`MANAGER` 增加成员、配置和索引维护，owner 或 `ADMIN` 额外拥有删除知识库权限。

## 状态管理

- JWT 和用户信息保存在 localStorage。
- 服务端数据使用 TanStack Query。
- 表单使用 React 受控组件。
- 文档任务通过 Query refetchInterval 轮询。

## API 层

`src/lib/api.ts` 统一处理：

- `VITE_API_BASE_URL`。
- JWT 自动注入。
- 401 自动清理登录态并跳转登录。
- 网络错误、超时、模型错误、服务端错误的友好提示。
- 解包后端统一响应 `{ success, data, error }`。

分页列表统一走 `normalizePage`，普通数组接口统一走 `normalizeArray`。页面层不要直接假设后端返回数组或分页对象，避免代理失败或接口变化时白屏。

## 错误处理

- `ErrorBoundary` 防止前端未捕获异常导致白屏。
- `ErrorMessage` 展示友好错误、错误编号和原始错误详情。
- 上传、检索、问答均展示局部错误，不影响整页使用。

## 上传交互

当前前端支持：

- 点击选择文件。
- 拖拽上传。
- 前端校验文件类型。
- 前端限制 50MB。
- 上传成功后刷新当前知识库文档列表。

## 视觉 QA

页面调整后至少检查：

- 桌面宽度 `1440x900`：首页、工单列表、工单详情、知识库目录、知识库详情、用户、租户、审计日志。
- 移动宽度约 `390x844`：确认没有横向滚动、按钮文字裁切、顶部账号菜单遮挡或底部导航覆盖主要操作。
- 工单详情页：队列、批量操作条、批量结果弹窗、客户问题、业务信息、沟通记录、AI 回复草稿、知识闭环、处理动作和时间线不能互相重叠。
- 工单权限态：无处理权限、已关闭、可关闭、可重开等状态下，分配、备注、沟通、状态流转、知识闭环按钮必须清晰禁用或显示对应动作。
- 售后运营看板：首页窗口切换、指标卡、趋势对比、坐席维度在桌面和移动端都不能互相重叠；移动端固定底部导航不能遮住关键操作。
- 知识库详情页：Tab 在移动端允许横向滚动，上传区和文档任务区不能挤压。
- 审计日志和首页最近管理动作：不要向用户展示 `SUPPORT_TICKET`、`KNOWLEDGE_BASE` 等内部动作码或目标类型码。

## 生产化注意事项

- 当前前端仍使用独立 Vite 开发服务。
- 生产环境建议构建静态资源后通过 Nginx 或对象存储 + CDN 部署。
- 后续可增加前端 Dockerfile、Nginx 配置、运行时配置注入和监控埋点。
