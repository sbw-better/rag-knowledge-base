# 需求规格说明

## 背景

企业内部常有大量业务文档、接口说明、操作规范、知识库文章和历史问答记录。普通关键词搜索无法稳定回答自然语言问题，也无法给出可追溯引用。本系统通过 RAG 流程，将文档解析、切分、Embedding、向量检索、混合检索和大模型问答串联起来，为不同业务场景提供可追溯的知识库问答能力。

## 用户角色

| 角色 | 当前能力 | 后续规划 |
| --- | --- | --- |
| ADMIN | 第一个注册用户自动成为管理员；可管理用户角色、创建和管理租户内知识库 | 更完整的组织、租户、审计和运营后台 |
| KB_MANAGER | 由 ADMIN 授权；可创建知识库，并自动成为自己创建知识库的负责人 | 更细的空间管理员、项目管理员能力 |
| USER | 注册登录；只能访问被授权的知识库问答入口 | 更细的 Viewer、Editor、只读/编辑权限 |
| 运维人员 | 查看日志、数据库、MinIO、健康检查 | 监控告警、任务重试控制台 |

## 核心功能

- 用户认证：注册、登录、JWT 鉴权、当前用户查询。
- 知识库管理：`ADMIN` 或 `KB_MANAGER` 创建知识库；负责人或 `ADMIN` 更新、删除、上传文档、配置 `chunkSize`、`chunkOverlap`、`topK`。
- 文档入库：上传文档到 MinIO，创建异步任务，解析文本、清洗、切分、生成向量并写入数据库。
- 检索：支持 `VECTOR`、`KEYWORD`、`HYBRID` 三种模式。
- 问答：基于检索片段构建 Prompt，调用 OpenAI-compatible Chat API，返回答案和引用来源。
- 会话：保存对话、消息和引用。
- 前端工作台：提供知识库、文档、检索、问答、设置等页面。

## 非功能需求

- 可运行性：本地可通过 Docker Compose 启动 MySQL + Milvus + MinIO，通过脚本启动后端。
- 可追溯性：问答结果必须返回引用片段、文件名、chunkIndex 和分数。
- 可维护性：后端按业务模块拆包，前端统一 API 层和错误处理。
- 可扩展性：保留租户字段、知识库成员表、模型客户端接口、存储接口，便于后续升级。
- 安全性：JWT 鉴权，生产环境校验默认密钥，生产不匿名开放 Swagger。

## MVP 范围

当前版本已实现：

- MySQL 存储业务数据和文档切片，Milvus 存储向量索引。
- MinIO 保存原始文件。
- DB 任务表 + Scheduler 处理异步入库。
- Apache Tika 解析 PDF、DOCX、TXT、Markdown、HTML。
- 简化关键词检索和混合检索。
- React 前端工作台。

当前版本暂不实现：

- RabbitMQ/Kafka。
- OpenSearch。
- OCR。
- Rerank 模型。
- WebSocket/SSE 流式输出。
- 复杂组织权限管理。
- 前端生产 Docker 镜像。

## 成功标准

- 新用户可注册登录；被授权为 `KB_MANAGER` 后可创建知识库，被授权为成员后可进入对应知识库问答。
- 用户可上传文档并看到任务状态。
- 文档处理成功后可检索到片段。
- 问答结果能返回答案和引用来源。
- 后端测试和前端构建检查通过。
